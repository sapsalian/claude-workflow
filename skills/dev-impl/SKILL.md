# /dev-impl 워크플로우

## 요구사항
$ARGUMENTS

## Step 1: Plan 선택

Glob 도구로 `.claude/plans/*.md` 파일 목록 확인.

- plan이 1개: 자동 선택
- plan이 여러 개: 목록 보여주고 선택 요청
- plan이 없음: "구현할 plan이 없습니다. dev-design 또는 dev-full로 먼저 설계를 진행하세요" 안내

## Step 2: 설계 검토

선택한 plan 전체 정독 (Context + 모든 Phase 세부 설계 + Sub-steps).

구현자 관점에서 능동적으로 검토 후 아래 형식으로 보고:

```
## 설계 검토 결과

### 구현 관점 우려 사항
- [구현 시 문제가 될 수 있는 설계 결정, 실현 가능성, 누락된 엣지 케이스 등]

### 보완 제안 (선택적)
- [구현하면 더 나은 부분이 있다면]

### 구현 전 확인 필요 사항
- [결정되지 않아 구현 시작 전 확인이 필요한 항목]
```

- 우려 없음: "검토 완료, 구현을 시작합니다." 후 진행
- 우려 있음: 보고 후 사용자 확인 → 해소 후 진행

## Step 3: Phase-by-phase 구현

각 Phase마다:

### 세부 설계 섹션 확인

- **채워진 경우**: `세부 설계` 섹션 읽고 바로 구현 시작
- **비어있는 경우**: "이 Phase는 세부 설계가 필요합니다. dev-design을 먼저 실행하거나 여기서 Q&A를 진행하시겠습니까?" 안내

### Phase 구현

plan 파일 해당 Phase 상태를 `[🔄 진행 중]`으로 업데이트.

sub-step이 있으면 각 step마다:
1. 테스트 먼저 작성 (인프라 없으면 먼저 구축)
2. 기능 구현
3. 테스트 실행 → 통과해야만 다음 step 진행
4. 중간 커밋
5. plan 파일 sub-step 카운터 업데이트: `(N/M)`

sub-step이 없으면:
1. 테스트 먼저 작성
2. 기능 구현
3. 테스트 + 빌드 실행 → 통과해야만 다음 단계 진행
4. 중간 커밋

### Phase 완료 처리

1. 빌드 실행 → 성공해야만 완료 처리
2. plan 파일 해당 Phase 상태를 `[✅ 완료]`로 업데이트
3. **Phase 완료 커밋 수행** (반드시)
4. 다음 Phase로 이동 / 없으면 전체 완료

## 전체 완료

- 모든 Phase `[✅]` 확인
- 최종 빌드 + 테스트 통과 확인
- 최종 커밋 (필요 시)
- plan 파일 상단 Status를 `complete`로 변경 + 완료 날짜 기록
